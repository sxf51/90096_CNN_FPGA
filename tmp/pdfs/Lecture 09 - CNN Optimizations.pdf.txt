// Tiled-convolution
for (n = 0; n < N; n += Tn) { // output feature
for (h = 0; h < H; h += Th) { // output height
for (w = 0; w < W; w += Tw) { // output width
for (c = 0; c < C; c += Tc) { // input feature
    // load input feature tile [c:c+Tc][h:h+Th][w:w+Tw]
    // load weight tile [n:n+Tn][c:c+Tc][0:K][0:K]
    // load output feature tile [n:n+Tn][h:h+Th][w:w+Tw]
    // tile calculation 
    for (tn = 0; tn < Tn; tn++) { // output tile feature
    for (th = 0; th < Th; th++) { // output tile height
    for (tw = 0; tw < Tw; tw++) { // output tile width
    for (tc = 0; tc < Tc; tc++) { // input tile feature
        for (kh = 0; kh < K; kh++) { // kernel height
        for (kw = 0; kw < K; kw++) { // kernel width
            out[tn][th][tw] += W[tn][tc][kh][kw] * in[tc][th+kh][tw+kw];
        }}
    }}}}
    // store output feature tile [n:n+Tn][h:h+Th][w:w+Tw]
}}}}

Fixed-point Conversion
Model conversion approach of [4]:
1. Apply floating point model to set of 
typical inputs and record all 
intermediate feature maps 
2. Calculate statistics on weights, 
biases, and output feature maps of 
each layer
3. Choose a fixed-point bit width b and 
step size 2-f for each item in (2) 
See [4] for discussion on choosing (3) 
for different distributions

Key Takeaways
1. Convolutional tiling will be required to fit SRCNN on Kria board
2. You have a design choices in tile size, tile order, and tile calculation 
pipelining/unrolling
3. Fixed-point conversion can allow more arithmetic units, and thus 
higher throughput, at a potential cost to output accuracy (MSE)
4. Global memory access (DRAM) likely to be a bottleneck in design, 
so important to consider dataflow and overlapping 
load/compute/store operations
