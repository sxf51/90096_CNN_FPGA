# SRCNN 超分辨率推理（Vitis HLS）

本项目用 C++ 实现三层 SRCNN 网络，并以 `srcnn` 作为 Vitis HLS 的综合顶层函数。代码读取预训练权重，对单通道、255 × 255 的输入图像进行推理，输出同尺寸的重建图像。`UP=3` 表示测试数据对应的 3 倍超分辨率任务；输入文件已经具有 255 × 255 的尺寸，网络本身不再改变宽高。

## 网络结构

| 层 | 输入通道 | 输出通道 | 卷积核 | 激活 |
| --- | ---: | ---: | ---: | --- |
| Conv1 | 1 | 64 | 9 × 9 | ReLU |
| Conv2 | 64 | 32 | 1 × 1 | ReLU |
| Conv3 | 32 | 1 | 5 × 5 | 无 |

卷积采用步长 1。Conv1 和 Conv3 在边界外重复最近的边缘像素，使各层特征图保持 255 × 255。权重和偏置为单精度浮点数；当前代码负责推理，不包含模型训练或图像插值步骤。

## 在 Vitis 中运行 C 仿真

1. 安装 Vitis 2026.1，并确认安装目录。
2. 打开 Windows **命令提示符（CMD）**，进入项目根目录，依次运行：

   ```bat
   chcp 65001
   call "<你安装Vitis的地方>\AMDDesignTools\2026.1\Vitis\settings64.bat"
   vitis -s script.py
   ```

   将 `<你安装Vitis的地方>` 替换为实际安装路径的前缀。`chcp 65001` 将控制台切换为 UTF-8，避免中文输出乱码；`call` 加载 Vitis 环境并返回当前 CMD 窗口，使下一条命令可以继续执行。

   **注意：**脚本每次运行都会删除并重建项目根目录下的 `workspace/`。如有需要保留的工作区内容，请先移出该目录。

3. 脚本结束后关闭该命令行窗口，在 Vitis GUI 中将工作区设为项目的 `workspace/`，打开 `baseline` 组件，运行 **C Simulation**。

配置文件位于 `workspace/baseline/hls_config.cfg`。目标器件为 `xck26-sfvc784-2LV-c`，目标时钟为 10 ns。C 仿真通过只表示功能结果得到验证；资源占用、时序和实际硬件性能需要另行运行 HLS 综合检查。

默认入口 `test/csim.cpp` 调用 Conv1 和完整网络的测试。若要运行 Set14 测试，按文件中的提示启用 `tb_set14()`。测试程序通过相对路径读取 `./weights/` 和 `./set5/` 等数据；Vitis 组件配置已把这些目录加入测试文件。

## 验证结果

使用项目提供的 butterfly 输入、权重及 golden 输出进行本地 C++ 对比，得到：

| 输出 | 与 golden 数据的 MSE |
| --- | ---: |
| Conv1 | 约 3.46 × 10⁻¹⁵ |
| 完整 SRCNN | 约 3.17 × 10⁻¹⁴ |

这些数值反映单精度计算与参考输出基本一致；它们不是与高分辨率真值图像比较的超分辨率质量指标。图像质量可通过 Set14 测试中的 MSE 和 PSNR 评估。

## FPGA 优化计划

本节是后续实施计划，**不代表以下优化已经实现**。计划以当前 `src/` 中的 255 × 255、单精度浮点 SRCNN 为基线，参考项目讲义中的分块卷积、数据流和定点化方法。每项改动先保持现有边缘复制填充与 golden 输出的功能一致，再比较 HLS 综合结果。

### 规模与定量依据

一层直接卷积的乘加数为 `H × W × Cin × Cout × K²`。`H × W = 255² = 65,025`；下表按一次乘法加一次累加计为一个 MAC，不含偏置、ReLU 和搬运开销。

| 层 | MAC 数 | 占总 MAC | 完整输出特征图（float32） | 权重（float32） |
| --- | ---: | ---: | ---: | ---: |
| Conv1：1→64，9×9 | 337,089,600 | 64.54% | 16,646,400 B | 20,736 B |
| Conv2：64→32，1×1 | 133,171,200 | 25.50% | 8,323,200 B | 8,192 B |
| Conv3：32→1，5×5 | 52,020,000 | 9.96% | 260,100 B | 3,200 B |
| 合计 | 522,280,800 | 100% | — | 32,128 B |

当前 `srcnn` 保存完整的 Conv1、Conv2 中间图，共 `24,969,600 B ≈ 23.81 MiB`。如果它们都写入并从外部存储器读回一次，仅这两组中间结果就需要 `2 × 24,969,600 = 49,939,200 B` 的传输；这是数据移动的下界，不是当前代码的实测 DRAM 流量。所有权重合计仅约 31.38 KiB（不含偏置），因此特征图的数据复用比反复优化权重加载更优先。讲义给出的 XCK26 片上 BRAM、URAM 容量也不足以直接容纳这两张 float32 全图。

### 阶段 0：测量基线

运行 C 仿真与 HLS 综合，保存各层循环延迟、II、实际时钟、DSP、LUT、BRAM、URAM，以及接口读写量。当前配置的 10 ns 是**目标时钟**，不是已测得的板上频率。以 100 MHz、每周期 1 MAC 粗算，纯计算至少需要 `522,280,800 / 10⁸ ≈ 5.223 s`；这只用于比较并行度，实际还受浮点运算延迟、存储端口与数据搬运限制。

### 阶段 1：分块卷积与局部复用

按输出通道 `Tn`、高度 `Th`、宽度 `Tw`、输入通道 `Tc` 分块。首轮候选为 `Th=Tw=32、Tn=8、Tc=8`，随后扫参数，而不预设其为最优值。采用**输出驻留**：输出块在本地累加完全部输入通道后写回一次，避免每个 `Tc` 块都读写 DRAM 部分和。输入与权重块进入本地缓冲；按综合报告对缓冲分区，保证并行读端口。

对 32×32 的 Conv1 输出块，9×9 核要求 4 像素 halo，输入区域为 `40×40`，即 `1,600×4=6,400 B`；8 个输出通道的 float32 累加块为 `8×32×32×4=32,768 B`，对应权重块为 `8×1×9×9×4=2,592 B`。Conv3 的 5×5 核需要 2 像素 halo：32×32 输出块对应每输入通道 36×36 输入。空间块越小，halo 的重复读取比例越高；Conv1 的 32×32 块为 `40²/32²=1.5625`，64×64 块则为 `72²/64²≈1.266`。更大的块也会增加片上容量，需用综合结果权衡。

在块内为 Conv1/Conv3 加行缓冲和滑动窗口，复用相邻像素的输入；对 `Tn`、`Tc` 和核内乘加做**部分展开**并流水化，不直接完全展开。Conv2 单独写成每像素 64→32 的 1×1 矩阵向量计算，去掉无效的核循环与边界判断。记录每组参数的 II、延迟与资源，选择满足目标器件限制的组合。

### 阶段 2：stream 与数据流

先把每个块拆为 `load → compute → store` 任务，以双缓冲和 FIFO/PIPO 配合 `DATAFLOW` 重叠三者。若单块加载、计算、写回分别花 `L、C、S` 周期，稳态目标是接近 `max(L,C,S)` 周期/块，而不是顺序执行的 `L+C+S`；启动、排空和总线争用仍要实测。外部 DRAM 使用适合连续地址突发的 AXI memory-mapped 接口；`hls::stream` 是核内或核间数据传递机制，不能自动保证 DRAM 突发访问。

再逐步让 Conv1→Conv2→Conv3 在片上以 stream/局部块传递，减少完整中间图读写。Conv2 对同一像素需要全部 64 个 Conv1 通道；Conv3 对每个输出像素需要全部 32 个 Conv2 通道和 5×5 邻域，因此流的通道顺序、行缓存与 FIFO 深度必须配套设计。若融合整个 32×32 最终输出块，Conv3 和 Conv1 的感受野半径合计为 `2+4=6`，原始输入至少需 `44×44` 区域（图像边缘按现有规则复制），而不是只取 32×32。成功消除两张中间图的一次外存写回与读回时，理论上最多减少约 49.94 MB/图的该类传输；实际收益以接口计数和板端时间为准。

### 阶段 3：量化和板端验证

浮点优化版本稳定后，对多张测试图统计每层激活、权重和偏置的范围，逐层选定位宽及足够宽的累加器，评估定点化。16 位特征图会把上述两张完整中间图的理论容量从约 23.81 MiB 降到约 11.91 MiB，但可能改变输出质量；最终以 MSE/PSNR、溢出检查和综合资源为准。检查 AXI 突发、传输时间与 PYNQ 主机调用开销，并比较 C 仿真、综合估计和板端实测。
