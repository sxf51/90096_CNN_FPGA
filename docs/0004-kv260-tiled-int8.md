# KV260 分块融合与 INT8 试验

此实现遵循 README 的分块、本地复用、减少中间图搬运与量化路线。默认保留 float32；`-DSRCNN_INT8=1` 启用实验量化版本。公开函数签名、255×255 尺寸、CHW 布局、运行时权重输入、两次 ReLU 和逐层边缘复制均保留。主要修改位于原 `implement ... here` 后；共享 Conv1 引擎及内部数值定义见 `src/tile.h` 和 `src/conv1.cpp`。

## 架构及参数依据

K26 官方资源为 117,120 LUT、234,240 FF、1,248 DSP、144 BRAM36K（即 288 BRAM18K）、64 URAM。BRAM 和 URAM 的物理容量合计约 2.883 MiB，仍远小于原两张中间图的 23.813 MiB。

来源：[AMD DS987](https://docs.amd.com/r/en-US/ds987-k26-som/Programmable-Logic)。

采用最终输出 `B=16`。float 的 Conv1/Conv2 输出通道并行 `P=8`、Conv3 空间并行 `V=1`；INT8 用 `P=16`、`V=4`，利用量化释放的容量。Conv3 需要 `S=B+4=20` 的前层特征；Conv1 再需要 `I=S+8=28` 的输入区域。每个最终块顺序执行 Conv1→Conv2→Conv3，只写最终输出。Conv1 的完整 64 通道局部块供 1×1 Conv2 复用，Conv2 的 32 通道局部块供 5×5 Conv3 复用。独立 conv1 使用 20×20 输出块，同一引擎不重复算融合所需的 halo。

同一核 tap 或输入通道先扫描全部 400 个像素，再更新下一 tap/通道。8 个通道并行、400 个独立部分和使浮点加法反馈间隔足够长；Conv3 以 256 个独立部分和隐藏反馈延迟。每个像素的累加仍保持原来的 ic→ky→kx 顺序。只部分展开输出通道，核 tap 和输入通道循环不完全展开。

| 本地数组 | float32 字节 | INT8 字节 |
| --- | ---: | ---: |
| 28×28 输入 | 3,136 | 784 |
| 64×400 Conv1 特征 | 102,400 | 25,600 |
| 32×400 Conv2 特征 | 51,200 | 12,800 |
| 两组 P×400 部分和 | 25,600 | 51,200 |
| 16×16 最终部分和 | 1,024 | 1,024 |
| 全部权重 | 32,128 | 8,032 |
| 偏置 | 388 | 388 |
| 合计 | 215,876 | 99,828 |

该表为逻辑容量预算，不等于实际 BRAM 分配；必须计入银行深度/宽度舍入、AXI FIFO 等。32×32 最终块单是两个 float 特征块就需 497,664 B，还未加入权重、部分和和接口，因此先选 16 而非直接用 README 的候选 32，给板上其余逻辑留冗余。没有采用仓库探索中的全核展开/宽窗口结构；例如 S04 的报告已有 LUT 97% 的占用，不满足余量要求。

16×16 分块产生 256 个块。含 halo 和尾块重复计算的 MAC 数：Conv1 530,841,600，Conv2 209,715,200，Conv3 52,428,800，总计 792,985,600。按前两层各 8 MAC/周期、末层 1 MAC/周期，纯 MAC 预算为 144,998,400 周期；加初始化、ReLU、接口和流水线开销后与约 147.85M 的综合结果一致。MAC 总量比原图增多，但避免了巨大存储且增加并行度。INT8 按 16/16/4 MAC 每周期的对应纯计算预算为 59,392,000 周期。Conv3 的 4 个空间银行令浅的 uint8 Conv2 缓冲产生 64 个小银行，选择 LUTRAM 避免每银行浪费一个 BRAM18K；逻辑位数仍只有 102,400 bit，约占 K26 分布式 RAM 总容量的 3%。最终显式按 channel/bank/address 存放并一次读取每个物理银行，核列偏移仅控制 4 个寄存器的轮换。INT8 仍使用宽累加器，不因提高并行度改变累加顺序。

源码层面的外部读取数量：输入 `256×28²` 个 float、全部权重/偏置一次，输出 65,025 个 float，合计 1,095,432 B/图；不再输出或读回两张中间图。这个数不含 AXI 对齐/协议/重复事务，尚未由板端总线计数证实。INT8 保留 float 外部接口，故不会自动进一步减少这部分流量。行内局部加载与输出支持连续地址，实际突发效果仍需集成后测量。

块边界的关键处理：先把 Conv2 所需的全局特征坐标截到图像边缘，再以该真实特征坐标取 Conv1 的输入 tap 并截边。仅对虚拟输入块截边会改变 Conv3 的边缘结果。尾块写回检查实际图像范围。

目前采用顺序的片上块融合，没有宣称已实现 stream、滑窗行缓存、DATAFLOW 双缓冲或 load/compute/store 重叠。浮点版双缓冲会显著减少当前的 BRAM 冗余，先以确定的容量和综合结果为准。

## INT8 数值方案

权重是 signed INT8（-127…127），输入和 ReLU 激活是 unsigned INT8（0…255），MAC 与偏置是 INT32；最后转回 float。无符号激活适用于非负 ReLU 输出，比 signed INT8 多一个有效范围位。对负偏置/权重仍采用有符号累加。

| 数值 | 编码倍率 | 可表达上界/范围 | 现有数据范围 |
| --- | ---: | ---: | ---: |
| 输入 | 255 | [0,1] | [0,1] |
| W1 | 192 | ±0.66146 | [-0.59940,0.53408] |
| A1 | 96 | [0,2.65625] | max 1.87276 |
| W2 | 128 | ±0.99219 | [-0.85179,0.66879] |
| A2 | 48 | [0,5.31250] | max 3.48685 |
| W3 | 640 | ±0.19844 | [-0.05460,0.16222] |

激活上界分别比校准最大值高约 42% 和 52%。偏置倍率为 48,960、12,288、30,720；第一层 ReLU 后采用正数四舍五入 `(acc+255)/510`，第二层为 `(acc+128)/256`，最后输出 `acc/30720`。权重量化为最近整数（正负半数均远离零）并饱和到 [-127,127]。INT8 输入要求有限、归一化到 [0,1]；其它运行时权重/数据仍会按照这些固定校准倍率量化，越界会饱和，不能把现有校准范围视为任意新模型的保证。

使用最保守的 INT8 范围，忽略偏置时累加绝对上界分别为 `81×255×127=2,623,185`、`64×255×127=2,072,640`、`800×255×127=25,908,000`。现有偏置编码很小，计入后均远低于 INT32 上限；第三层最坏情况至少需 26 位有符号数，INT32 留出 6 位冗余。真实 14 张图的最大绝对累加为 91,087 / 42,767 / 31,453，激活最大码值 179 / 167，饱和计数均为 0。统计见 `validation/kv260/int8_ranges.json`；校准见 `calibration.json`。

## 功能与图像质量

以冻结的原始 C++ 实现作独立参照，测试 butterfly、仓库现有 13 张 Set14 图、全 1 图、四边脉冲图，以及下一次调用时修改权重和偏置。默认 float 在所有 17 次整网测试逐像素一致，最大误差和六像素边带误差均为 0。独立 conv1 的 butterfly 和两张构造图也逐像素一致。golden 文件的 butterfly MSE 为 Conv1 3.46254e-15、整网 3.1661e-14。

INT8 14 张真实图的相对 float MSE 为 8.67664e-5…2.76199e-4，最大绝对像素误差 0.05491。与高分辨率真值比较，平均 PSNR 下降约 0.644 dB，最差 foreman 下降约 2.470 dB；butterfly 下降约 0.439 dB。此处 PSNR 统一在 [0,1] 上截幅后按浮点差计算，不使用原测试中可能发生 uint8 回绕的转换。因此质量表以这里同一计算方法下的 float/INT8 比较为准。完整结果见两个 `*_quality.csv`。

校准和质量评估只覆盖已提供的图像；Set14 的 comic 未提供，不能称为完整 Set14 验收。INT8 质量下降可见，故默认 float32；INT8 提供为可复现实验开关，不默认替换精度。

## Vitis 2026.1 最终综合结果

目标 `xck26-sfvc784-2LV-c`，10 ns 时钟，`pipeline_loops=0`，保留显式流水线。以下是 HLS 估计，不是已布局布线或板端实测的性能。

| 版本 | 周期 | 100 MHz 下估计延迟 | BRAM18K / 288 | DSP / 1248 | LUT / 117120 | FF / 234240 | URAM |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 原始浮点基线 | 4,482,223,011 | 44.822 s | 11,064，无法容纳 | 5 | 2,217 | 1,267 | 0 |
| 默认分块 float32 | 147,849,536 | 1.478 s | 151 (52.43%) | 45 (3.61%) | 17,204 (14.69%) | 14,025 (5.99%) | 0 |
| 可选分块 INT8 | 60,967,603 | 0.610 s | 96 (33.33%) | 112 (8.97%) | 31,608 (26.99%) | 12,547 (5.36%) | 0 |

浮点版留出约 48% BRAM，INT8 留出约 67% BRAM、73% LUT 和 91% DSP，所有 URAM 都未使用。原始基线资源超限，不能将其 44.822 s 当成可在 KV260 实现的实测基线。两种新版本的 HLS 关键路径估计均为 7.300 ns，时钟不确定度 2.70 ns；它不是板上已经达到 137 MHz 的证明。

最终所有要求流水线的循环达到 II=1（包括 Conv1 tap/pixel、Conv2 ic/pixel 和 Conv3 tap/pixel）。曾用循环分区的扁平 Conv2 数组时，动态 kx 地址使工具对 4 次读取保守调度为 II=2；最终改用 `c2[channel][bank][address]` 显式四银行，每银行固定读取一次，再在 4 个寄存器间轮换，恢复 II=1，延迟从 74,074,803 降至 60,967,603 周期。LUT 从该控制版本的 35,907 降至 31,608。

INT8 DSP 总数仍高于默认浮点版：并行度提高，且 float 参数/图像接口需要运行时量化转换，整数重定标也有成本。因此不能简单按位宽比例推断整核 DSP 收益；该配置是用实际综合资源换取约 2.43 倍的 float 分块版估计速度，并保留余量。主报告和各模块 II XML 已保存在 `validation/kv260/reports/`，`synthesis_summary.json` 记录资源、周期、II 与生产源文件 SHA256。

## RTL 联合仿真结果

最终 INT8 实现于 2026-10-12 通过 Vitis 2026.1 / XSIM 的 C/RTL 联合仿真（Verilog Pass）。测试为 17×17 两帧，覆盖四边、跨 16×16 分块及第二次调用修改权重和偏置。两帧相对原始 float 参考的 MSE 分别为 0.000307081 和 0.000143540，最大误差分别为 0.0468301 和 0.0433072；RTL 输出通过 C 后检查。每帧 RTL 延迟为 968,755 周期，仅用于说明缩小测试已完成，不能代表 255×255 性能。

报告与完成日志摘录保存在 `validation/kv260/reports/cosim/`。完整 255×255 的 float/INT8 已通过 C 仿真和综合；本次 RTL 联合仿真仅验证上述缩小尺寸的 INT8 配置，未完成完整尺寸 RTL 联合仿真。

## 复现

从仓库根目录运行 PowerShell：

```powershell
./validation/kv260/verify.ps1
./validation/kv260/verify.ps1 -Int8
python validation/kv260/calibrate.py
python validation/kv260/int8_ranges.py
```

需要 g++（C++17）和 NumPy。原始参考快照仅位于 `validation/kv260/baseline_*.cpp`，用于独立对照及原版基线综合，不参与优化版综合。`verify.ps1` 的非零退出表示断言失败；质量阈值是试验的基本数值检查，不代表 INT8 已满足最终视觉质量要求。

Vitis 批处理（已使用用户提供的 2026.1 安装）：

```bat
validation\kv260\run_hls.bat float
validation\kv260\run_hls.bat int8
validation\kv260\run_hls.bat baseline
python validation\kv260\prepare_reduced.py
validation\kv260\run_hls.bat reduced
```

每次创建新的时间戳工程，不删除已有工作区。Tcl 先切换到验证目录，并在关闭生成工程后把 hls.app 中的设计源码路径规范成绝对路径再重开，避免此 Windows 安装的相对路径解析问题；源码和编译选项不变。float/int8 执行完整尺寸 C 仿真和综合；reduced 执行 17×17、两帧、参数变化、四边及跨 16×16 块的 C 仿真和 XSIM 联合仿真。其源文件由生产版本复制，仅改变 H/W 和相应 AXI depth，不能用缩小测试的延迟代替完整帧性能。设置 `SRCNN_COSIM=1` 可对完整 float/int8 工程运行整帧 cosim，运行时间会显著更长。

未连接实体板卡；没有宣称布局布线时序、硬件吞吐或板端 PSNR 已验收。需在 KV260 集成 AXI master 与控制寄存器后测量实际时钟、DDR 行为和主机调用耗时。
