# SRCNN FPGA 加速：结合 Lecture 08 和 Lecture 09 的中文讲稿

建议 7 页，约 8–10 分钟。所有课件引用均为 PDF 文件页码，Lecture 09 的 PDF 页码比正文印刷页码大 1。当前已上板设计为分块 float32；F25 是独立的后续候选，不能混为同一个实现。

## 第 1 页：加速的算法是什么？

**页面内容：** 输入图像 → 9×9、64 通道、ReLU → 1×1、32 通道、ReLU → 5×5、1 通道 → 输出图像。配 butterfly 输入、硬件输出与参考图。

**讲稿：**

我的项目是在 Kria KV260 上加速 SRCNN，也就是用于图像超分辨率的三层卷积神经网络。这里实现的是使用已有权重的推理过程。

按照 Lecture 08 对 SRCNN 的介绍，第一层用 64 个 9×9 卷积核提取局部特征；第二层用 1×1 卷积组合这些通道，输出 32 个特征；第三层用 5×5 卷积将特征重建为图像。前两层使用 ReLU，最后一层保留线性输出。

Lecture 09 还列出了前置的 bicubic 插值。本项目测试数据已经完成相应的输入准备，当前 IP 加速的是后面的三层卷积。测试尺寸为 255×255，步长为 1，采用边缘复制的 same padding。因此，验证时除了图像内部，也要检查边缘和分块交界是否与参考程序一致。

**课件依据：** Lecture 08，第 21、26 页；Lecture 09，第 3 页。

## 第 2 页：为什么适合硬件加速？

**页面内容：** 六重循环示意；每帧约 5.22 亿 MAC；空间、输出通道并行；权重和输入复用。

**讲稿：**

Lecture 08 把卷积表示为六重循环：输出通道、输出高度、输出宽度，以及输入通道和卷积核的两个空间维度。卷积的主要工作就是反复执行乘加，因此计算规律，具有明确的并行机会。

每层的乘加量可以用高度乘宽度，再乘输入通道、输出通道和卷积核面积来计算。对于本项目的 255×255 输入，三层总共需要约 5.22 亿次 MAC，其中第一层约占 65%，第二层约占 25%，第三层约占 10%。这些是原始算法的运算比例，不等于优化后硬件的时间比例。

不同输出位置和输出通道可以并行计算，但单个输出的累加仍然存在依赖。因而需要选择合适的流水线和部分展开方式，并通过存储分区提供足够的读写端口。

此外，同一个卷积核会用于很多位置，同一个输入也会参与多个输出计算。这对应课件中的参数复用和局部连接，是通过片上缓存降低外部访存的基础。硬件加速的关键，是让计算并行度与存储供数能力相匹配。

**课件依据：** Lecture 08，第 18–20、30–31 页；Lecture 09，第 12、21 页。

## 第 3 页：首先解决存储容量，再选择并行度

**页面内容：** 原始完整特征图 → 16×16 输出块；28×28 输入块；20×20 中间区域。列出 BRAM18K：11064 → 151。

**讲稿：**

第一阶段最明显的问题是存储容量。原始浮点实现保留两层完整中间特征图，仅这两组数组就需要约 23.8 MiB。原始 HLS 报告估计需要 11064 个 BRAM18K，而目标器件只有 288 个，因此这套存储结构无法部署。

这直接对应 Lecture 09 的 tiled convolution：不同时保存整幅特征图，而是按块读取、计算和写回。我目前采用 16×16 的最终输出块。因为前后卷积都需要邻域数据，每块实际需要 28×28 输入，以及 20×20 的中间特征区域。

权重在一次调用开始时加载，并复用于所有块；输入块在片上复用于多个输出通道；局部累加结果保留在片上，完成后才写回。这分别体现了课件中 weight stationary、input stationary 和 output stationary 的复用思想，但当前实现并非只采用其中一种。

分块后，float HLS 的 BRAM18K 估计降到 151，存储结构变得可实现。代价是相邻块的边界区域需要重复计算：每帧 MAC 从约 5.22 亿增加到 7.93 亿，增加约 52%。这正是课件讨论的 tile 边界开销。因此后续会比较更大的块和流式行缓存，减少重复工作，同时确保片上容量和时序仍有余量。

**课件依据：** Lecture 08，第 33 页；Lecture 09，第 13、15–21 页。

## 第 4 页：目前已完成哪些验证？

**页面内容：** 正确性、图像质量、部署和资源表；避免把 HLS 改善写成 CPU 加速比。

| 指标 | 已完成的结果 |
|---|---:|
| butterfly 板端与参考的 MSE | 3.166×10⁻¹⁴ |
| 最大绝对误差 | 9.54×10⁻⁷ |
| 13 张 Set14 输入平均 PSNR | 27.589 dB |
| 硬件输出平均 PSNR | 29.159 dB |
| 平均图像质量提升 | 1.570 dB |
| 完整系统 DSP / LUT 使用率 | 3.69% / 8.79% |
| 完整系统 BRAM 使用率 | 50.35% |
| 布线后 WNS / TNS | +3.648 ns / 0 ns |

**讲稿：**

目前，float 版本已经完成 HLS 综合、完整 Vivado 系统实现、bitstream 生成和板端测试。butterfly 的硬件输出与参考程序的均方误差约为 3.17×10 的负 14 次方，最大误差小于一百万分之一。重复调用和修改偏置后的测试也通过了，说明除了单次输出，调用状态和参数更新也符合预期。

在已提供的 13 张 Set14 图像上，平均 PSNR 从输入的 27.589 dB 提升到 29.159 dB，平均提高 1.570 dB。这里衡量的是相对于高质量目标图像的重建效果，不能把这 1.570 dB 当成硬件相对于同算法软件的质量改善。

从两个 HLS 模型看，原始基线到当前分块版本的周期数改善约 30.3 倍。但是原始结构不能放入器件，因此这只是模型比较。当前尚未完成同条件的 CPU 基准，暂时不能报告 FPGA 对 CPU 的实际加速比。

完整系统的 DSP 使用率仅约 3.7%，BRAM 已使用约一半。布线后时序满足 100 MHz 约束。这个结果表明设计已经可以部署，也提示后续提高并行度时，必须同时检查存储端口、资源增长和布线时序。

**证据：** docs/0006-hardware-acceleration-review.md；validation/kv260/synthesis_summary.json；project/project.runs/impl_1/design_1_wrapper_utilization_placed.rpt；project/project.runs/impl_1/design_1_wrapper_timing_summary_routed.rpt；已执行的板端 notebook。

## 第 5 页：实际性能瓶颈是什么？

**页面内容：** 100 MHz 设计时钟 vs 66.666 MHz 运行时钟；实测 2.238 s；模型换算 2.218 s。画 PS 控制与 DDR 数据两条通路。

**讲稿：**

板端平均耗时约 2.238 秒，也就是每秒约 0.447 帧。最初它比 HLS 在 100 MHz 下估计的 1.478 秒慢很多。进一步读取运行时钟后发现，PL0 实际寄存器配置对应 66.666 MHz。把相同的 HLS 周期数按这个频率换算，得到约 2.218 秒，已经接近实测结果。因此当前首先需要解决的是设计时钟和运行时钟不一致。

Lecture 09 区分了 AXI-Lite 控制和 AXI memory-mapped 数据访问。本设计使用 AXI-Lite 配置参数、启动计算和读取完成状态；图像与权重通过三个 AXI 主接口，经 SmartConnect 和 PS 的 HP0 访问 DDR。

模型换算与实测之间剩下约 19.8 毫秒，占总耗时约 0.88%。这个差额包含可能的 AXI 等待、主机轮询和模型误差，不能直接当作 DDR 总开销，因为 HLS 模型本身也包含访存调度。当前结果尚不足以认定 DDR 带宽是主要瓶颈。

计算方面，HLS 每块估计显示第一层约占 46%，第三层约占 35%。因此下一步会优先评估这些层的并行度。虽然内部部分循环达到 II=1，三层之间仍然顺序执行；只有引入合适的 FIFO 和 DATAFLOW，才可能形成课件所讲的生产者与消费者重叠执行。

**课件依据：** Lecture 08，第 38–39 页；Lecture 09，第 27、31–33、36–37 页。
**证据：** docs/0005-kv260-board-clock.md；docs/0006-hardware-acceleration-review.md。Clocks 为寄存器推算频率，非仪器测量。

## 第 6 页：量化和流式架构有哪些探索？

**页面内容：** float → 校准 → INT8 / 10 位候选；性能、精度、资源三者权衡。

**讲稿：**

Lecture 09 指出，定点量化需要分别选择数值范围和分辨率。位宽缩小能减少存储和算术成本，但也可能产生饱和或舍入误差。因此位宽不能只按 INT8 这个名称决定，而要先使用代表性输入记录权重和中间激活范围，并保留余量。

本项目已经实现了可选 INT8 版本，使用整数乘加和更宽的累加器。在 100 MHz 下，HLS 估计延迟约为 0.610 秒，比当前 float 模型快约 2.43 倍，并且完成了 17×17、两帧的 RTL 联合仿真。不过平均 PSNR 下降约 0.644 dB，最差图像下降约 2.470 dB。因此它仍需要完整尺寸和板端验证，并评估质量是否满足要求。

仓库中还有采用 10 位权重与激活、流式行缓存的 F25 候选。这条路线符合课件的量化和数据流思路：用更合适的精度换取并行算术资源，用连续数据流减少完整缓存和重复取数。已有 13 张图的测试，相对它自己的浮点参考，平均 PSNR 下降约 0.070 dB，两帧 RTL 仿真也通过了。

但 F25 的 2.64 毫秒是基于 400 MHz 目标的 HLS 估计，尚无成功布线和上板证据，所以不能报告为实测性能。它也需要更多 LUT 和寄存器。接下来要验证的是它在 KV260 上能否满足时序、保留资源余量，并在实际系统中达到预期吞吐。

**课件依据：** Lecture 09，第 8、23–24、27、36 页。
**证据：** validation/kv260/synthesis_summary.json；validation/kv260/reports/cosim/srcnn_cosim.rpt；experiments/F80_final_all_supplied_F25/config.json；experiments/F82_final_cosim_F25/config.json；experiments/F81_final_impl_F25/config.json。

## 第 7 页：剩余任务及预期结果

**页面内容：** 时钟 → 测量 → 并行度扫描 → 精度/流式候选 → 最终验收。

**讲稿：**

接下来，我会首先在 IP 空闲时检查并调整 PL0 到 100 MHz，再重新运行正确性和计时测试。如果周期数保持接近当前水平，预计 float 板端耗时可以降到约 1.49 秒，这个预测主要来自时钟比例，还需要实测确认。

第二，补充相同输入、同算法和同精度的 CPU 基准，并明确计时范围。同时增加硬件周期计数和 AXI 性能测量，区分计算、数据传输与软件控制开销，形成可复现的加速比。

第三，按 Lecture 09 的设计参数扫描方法，逐项比较 tile 大小、通道展开和存储分区。当前 DSP 占用较低，因此有提高并行度的空间，但收益必须由综合和实际布线结果确认，不能按剩余 DSP 数量直接推算。

第四，继续比较 INT8 与 10 位定点的精度，并验证流式行缓存和层间 DATAFLOW。对于 F25，我会先完成独立实现，再进行完整图像、边界、连续调用和参数更新的板端验收。

最终希望给出一组明确的比较：每个方案在实际时钟下的耗时、图像质量、资源使用和时序余量。当前已经证明分块架构可以在 KV260 上正确运行；后续工作将验证如何在精度和资源约束下进一步提高速度。

**课件依据：** Lecture 09，第 15–16、21、24、38 页。
