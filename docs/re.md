目前完成的优化可以概括为：**分块降低存储需求、片上复用减少数据搬运、部分并行和流水线提高吞吐，以及可选 INT8 量化。** 已上板的是 float32 版本；INT8 是已完成综合和部分 RTL 验证的实验版本。

下面这段可以用于报告。

### 1. 分块计算与三层片上融合

原始实现保存整幅 Conv1 和 Conv2 特征图，两组 float32 中间数据约需 **23.81 MiB**，超过 KV260 的片上存储容量。因此，将完整图像计算改为按最终输出块处理。

参数定义在 [tile.h](D:/AMyUni/2026S2/golden/src/tile.h:17)：

| 参数 | 设置 | 依据 |
|---|---:|---|
| 最终输出块 `B` | 16×16 | 控制局部缓存规模，保留资源余量 |
| 中间特征区域 `S` | 20×20 | `S=B+F3−1=16+5−1` |
| 输入区域 `I` | 28×28 | `I=S+F1−1=20+9−1` |
| 图像尺寸 | 255×255 | 保持原始算法和测试接口 |
| 块数 | 16×16＝256 块 | 每个方向向上取整，尾块检查写回范围 |

每块依次执行 **Conv1 → Conv2 → Conv3**，两层中间特征保存在片上，只向 DDR 写回最终输出。

选择 16 而非直接使用 32，是因为 32×32 输出块对应的两组 float 中间特征就需要约 **486 KiB**，还未包含权重、部分和及接口缓存。16×16 是目前验证通过的保守设计点，尚不能称为最优。

**效果与代价：** HLS 的 BRAM18K 估计从 11064 降至 151；但相邻块的边界重复计算使每帧 MAC 从约 5.22 亿增至 7.93 亿，增加约 52%。

### 2. 权重缓存与输入复用

所有权重在**每次调用开始时加载一次**，随后复用于全部 256 个块；每个输入块也只加载一次，再供多个输出通道使用。

| 数据 | 复用方式 |
|---|---|
| 各层权重 | 一次调用内跨块复用 |
| 输入块 | 跨 Conv1 输出通道复用 |
| Conv1 特征块 | 供 Conv2 的多个输出通道复用 |
| Conv2 特征块 | 供 Conv3 的不同卷积位置复用 |
| 局部累加结果 | 完成累加后才输出 |

这减少了反复从 DDR 读取权重和搬运中间特征的需求，同时保留运行时更新权重的能力。

按源码访问数量计算，每帧外部数据量约 **1.095 MB**；这是逻辑访问量，尚不是 AXI 总线实测流量。

### 3. 部分循环展开，增加通道和像素并行度

采用 `UNROLL` 展开较小的 lane 循环，而不是完全展开卷积核和输入通道循环。

| 并行参数 | 默认 float32 | 可选 INT8 |
|---|---:|---:|
| Conv1、Conv2 输出通道并行数 `P` | 8 | 16 |
| Conv3 像素并行数 `V` | 1 | 4 |

float 使用 8 路通道并行，在提高吞吐的同时控制存储端口和资源需求。INT8 的特征缓存更小，因此进一步提高通道和像素并行度。

这些参数是经过容量预算和综合验证的可行配置，**不是按 DSP 剩余数量直接推算出的最优值**。

### 4. 调整循环顺序并加入流水线

加载、初始化、卷积计算、ReLU 和写回循环采用：

```cpp
#pragma HLS PIPELINE II=1
```

计算时，对一个卷积核位置或输入通道先扫描全部像素，再处理下一个位置或通道：

- Conv1、Conv2：轮流更新 400 个独立像素的部分和。
- Conv3：轮流更新 256 个输出像素的部分和。

这样拉长同一个累加值再次被访问的间隔，减轻浮点加法反馈依赖，同时保持每个像素原有的累加顺序。

最终综合报告中，这些显式流水线循环达到 **II=1**。不过，三层和各块仍顺序执行，尚未实现层间 DATAFLOW 重叠。

### 5. 数组分区与存储器绑定

在 [srcnn.cpp](D:/AMyUni/2026S2/golden/src/srcnn.cpp:40) 中，存储组织与计算并行度配套设置：

| 对象 | 配置 | 目的 |
|---|---|---|
| 权重和特征的通道维 | `cyclic factor=P` | 为并行通道提供独立访问 |
| `partial` 的 lane 维 | `complete dim=1` | 各通道独立更新部分和 |
| 权重缓存 | 单端口 BRAM | 权重加载后供计算读取 |
| float 特征、部分和 | 双端口 BRAM | 支持计算中的读写 |
| INT8 Conv2 特征 | 空间分 bank，使用 LUTRAM | 支持四像素并行，减少浅 bank 的 BRAM 浪费 |

INT8 的 Conv2 缓冲进一步改为：

```cpp
c2[channel][bank][address]
```

每周期固定读取四个物理 bank，再通过寄存器轮换匹配卷积位置。这解决了动态地址导致的端口冲突判断，使 Conv3 从 **II=2 恢复为 II=1**，INT8 总周期数从约 7407 万降至 6097 万。

### 6. AXI 数据与控制接口配置

| 参数 | 设置 |
|---|---|
| 输入图像接口 | `m_axi`，`bundle=image_in` |
| 权重和偏置接口 | `m_axi`，共享 `bundle=params` |
| 输出图像接口 | `m_axi`，`bundle=image_out` |
| 软件控制接口 | `s_axilite`，`bundle=control` |
| 输入最大读 burst | 64 拍 |
| 输出最大写 burst | 64 拍 |
| 图像 `depth` | 65025 个元素 |

三个数据接口通过 SmartConnect 接到 PS 的 HP0。分开 bundle 可以分离接口请求，但最终仍共享 HP0 和 DDR。

64 拍是突发长度上限，实际能否形成长 burst 取决于访问连续性和综合结果，尚需性能计数验证。

### 7. 可选 INT8 量化

默认保留 float32；编译时使用 `-DSRCNN_INT8=1` 启用内部量化。

| 数据 | 类型 | 编码倍率 |
|---|---|---:|
| 输入 | `uint8_t` | 255 |
| Conv1 权重 | `int8_t` | 192 |
| Conv1 ReLU 激活 | `uint8_t` | 96 |
| Conv2 权重 | `int8_t` | 128 |
| Conv2 ReLU 激活 | `uint8_t` | 48 |
| Conv3 权重 | `int8_t` | 640 |
| 偏置、累加值 | `int32_t` | 按对应输入与权重倍率设置 |

量化关系为 `整数值≈round(浮点值×倍率)`。倍率依据提供的权重和代表性图像校准：

- Conv1 激活可表示至 **2.65625**，校准最大值约 1.87276，留约 42% 余量。
- Conv2 激活可表示至 **5.3125**，校准最大值约 3.48685，留约 52% 余量。
- 累加使用 INT32，避免只用 8 位累加造成溢出。

外部接口仍是 float，因此 INT8 主要减少内部存储和计算成本，**不会自动减少 DDR 接口字节数**。

### 当前结果

以下为统一按 100 MHz 换算的 **HLS 估计**：

| 指标 | 分块 float32 | 分块 INT8 |
|---|---:|---:|
| 周期数 | 147,849,536 | 60,967,603 |
| 估计延迟 | 1.478 s | 0.610 s |
| BRAM18K／288 | 151 | 96 |
| DSP／1248 | 45 | 112 |
| LUT | 17,204 | 31,608 |

float 已完成上板验证，完整系统实际 BRAM 使用率为 **50.35%**。INT8 相对 float 的 HLS 估计快约 **2.43 倍**，但平均 PSNR 下降约 **0.644 dB**，因此尚未替换默认版本。

汇报时可以概括为：

> 当前首先通过分块和片上融合解决存储容量问题，再通过权重复用、8 路通道并行、数组分区和 II=1 流水线提高吞吐。可选 INT8 进一步降低内部存储需求并提高并行度，但存在图像质量损失。参数选择以容量预算、数值校准和综合报告为依据，并保留资源余量；流式行缓存、层间 DATAFLOW 和双缓冲仍属于后续工作。
