2026-10-12，在板端 srcnn_hls.ipynb 新增只读诊断单元，使用 pynq.Clocks 读取运行时频率，没有改变时钟或重新下载 overlay。

此前把 GUI 的 99 MHz 当成实际 99 MHz 不准确：HWH 是约 100 MHz。HWH/约束是设计值，运行时 Clocks 读取值反映当前 PLL/分频设置；不等于示波器测量。
约 50% 延迟差距主要由 100 MHz 设计值和 66.666 MHz 运行值的差异解释。
HWH 请求 PL0 使用 IOPLL，DIVISOR0=15、DIVISOR1=1。可能是板上启动环境的 PLL 与 Vivado 初始化设置不同；未逐项读取实际 PLL 源和分频，不能断言具体初始化原因。

剩余 19.8 ms 是 AXI/DDR 等待、主机轮询/调度和模型误差的混合项，不是直接测得的 DDR 延迟。HLS 基线也已经包含模型化的访存调度，因此该差额不是总访存时间。
当前每帧逻辑访问量：256块×28×28×4=802816 字节输入读取，255×255×4=260100 字节输出，参数32516字节，合计1095432字节；不是 AXI 总线实际计数。不能用此字节数除以整网耗时当作 DDR 极限带宽。
现有设计没有 AXI Performance Monitor/ILA/硬件周期计数器，无法精确拆分 burst 长度、等待周期和 DDR 吞吐。
分块输入夹边地址可能限制突发合并，但只是优化候选；当前结果不支持认定 DDR 带宽是主瓶颈。

下一步在 IP idle 状态，通过 PYNQ 只调整 PL0（不更改 PS PLL 全局设置）至100MHz，再读取确认并重跑功能和延迟；本次未执行修改。
如果周期近似不变，则预期延迟约1.492 s（不是保证）。进一步精确测量需要增加同域AP_START/AP_DONE周期计数，以及AXI Performance Monitor统计请求/数据拍和延迟。
