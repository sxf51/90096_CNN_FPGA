## 6. Interpretation / 解读

The frozen F28 RTL completes its independent out-of-context implementation at a 5 ns constraint. Final setup slack is +0.282 ns with zero TNS; the final report also has +0.029 ns hold slack, zero pulse-width violations and zero unrouted nets. This establishes timing closure at the tested 5 ns target. The slack-derived 4.718 ns period has not been independently implemented and is not an accepted faster clock.

Physical resources are 591 DSP, 30,140 LUT, 76,498 FF and 72 BRAM18K equivalents, with no URAM. The memory count is 28 RAMB36 plus 16 RAMB18. Compared with the frozen HLS predictions, LUT falls to 48.97% and FF to 62.67%; these exceed the twenty-percent deviation criterion. HLS counts scheduled module logic before whole-RTL optimization, while Vivado optimizes that RTL and maps storage into primitives. The physical hierarchy must locate the difference before attributing it to a particular loader or multiplier. DSP instead rises from 502 to 591, so the LUT reduction cannot be applied to other resource estimates. Preserve the original HLS acceptance gates.

F93 independently measured two exact RTL transactions with changed runtime parameters: maximum latency 1,059,506 cycles and interval 1,059,535. At F95's timing-closed 5 ns target the corresponding IP-level frame time is 5.29753 ms. It is 0.8123% below F25's independently verified 5.340915 ms, consistent with F28's reduced startup cost. The HLS 2.5 ns target and 2.6150725 ms estimate have not been established by this route. Ideal RTL AXI behavior and OOC timing still require system and board validation.

The initially available worst setup path is inside Conv1's local weight loading: an address register drives private LUTRAM WADR1. It has zero logic levels, a 4.541 ns data path and no DSP cascade. This differs from W20's Conv3 window clock-enable path; use each candidate's own evidence. The five-path checkpoint export and physical hierarchy are pending behind the serial hardware lock, so this first path is not yet a five-path bottleneck census.

Implementation takes 46.52 minutes, plus 0.52 minutes for packaging. Archived memory samples show a minimum 3.68 GiB available and 10.96 GiB peak aggregate tool RSS; the run completes without OOM within the three-hour limit. The original full-run trace predates CPU telemetry, so CPU utilization remains unknown there; the separately labeled short sample cannot establish full-run throughput or a threading benefit.

Keep F28 as the strictly accepted T16 fallback. Finish W21's own changed-parameter RTL and routed verification, then choose the single remaining WS4 physical-clock probe from its paths. Missing comic keeps the thirteen-image quality result provisional, and no board acceptance is claimed.

Continuous scheduling separates window generation and MAC folds, shifts channel registers and explicitly registers fabric reduction trees. This can remove pixel fill/drain but costs pipeline registers and wide window FIFOs. Online padding overlaps source reads with padded writes; old row serialization can create finite-FIFO stalls absent from maximum-component HLS estimates. RTL cycles and routed slack remain the final evidence.
