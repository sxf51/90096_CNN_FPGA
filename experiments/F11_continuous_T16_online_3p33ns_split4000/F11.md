# F11: continuous_T16_online_3p33ns_split4000

## 1. Purpose and hypothesis / 目的与假设

W11 C simulation passes exactly but synthesis rejects the8000-bit aggregated Conv3 stream with HLS214-256: maximum4096 bits. Preserve the continuous schedule and represent one800-element window as two25x16-channel4000-bit packets, each below the measured limit. Both streams produce/consume65025 packets per frame; no quantization or MAC change. Separate window production from convolution engines, flatten pixel/fold loops into oneII1 loop and shift fixed channel registers each fold. Register balanced fabric reductions to break E070's eight-DSP unregistered adder path. Online padding caches the first row and reads/emits subsequent rows together, avoiding pad3's serialized row phases.

## 6. Interpretation / 解读

Compare the frozen estimates with parsed hardware reports. This is a representation fix for the compiler's4096-bit aggregate limit, not a precision relaxation. Check both stream counts and achievedII; final selected points still require full-supplied-image verification and finite-FIFO RTL cosimulation.

Continuous scheduling separates window generation and MAC folds, shifts channel registers and explicitly registers fabric reduction trees. This can remove pixel fill/drain but costs pipeline registers and wide window FIFOs. Online padding overlaps source reads with padded writes; old row serialization can create finite-FIFO stalls absent from maximum-component HLS estimates. RTL cycles and routed slack remain the final evidence.

Explicit explanation of deviations above20%:

The paper cache estimate used stored-bit capacity, whereas channel/row banking and shallow-wide FIFO mapping consume whole memory primitives. Explicit LUTRAM and URAM bindings change that granularity. Registered reductions add pipeline FF and address/window FIFOs while continuous loops remove per-pixel drain; compare the memory counts and folded iteration depths to the storage controls. HLS maximum-component cycles still exclude finite-FIFO stalls, especially with old row-serialized padding.

The online Conv3 pad row is explicitly aggregated into 320-bit words and its parsed module uses 9.0 BRAM18K. This packs channel fields into wide memory ports, whereas F08's old pad control leaves individual channel fields in separate banks. That storage-fragmentation change explains the BRAM saving independently of the Conv3 rotation or MAC count.

Observed fold depth/II: continuous_c2_fold depth=12, II=1.0; continuous_c1_fold depth=13, II=1.0; continuous_c3_fold depth=13, II=1.0.
