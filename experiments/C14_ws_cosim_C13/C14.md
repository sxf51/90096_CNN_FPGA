## 6. Interpretation / 解读

Both complete RTL transactions pass bit for bit. The first butterfly frame uses the independently validated E065 mixed Conv2-weight reference; the second changes input, weights and bias and checks every output against104/256. The unchanged border metric is1.405191888267716e-05. The finite-FIFO run measures300632 latency cycles and300661 interval cycles, compared with263090 HLS cycles (+14.269642%) and the292000 architecture expectation (+2.956164%). Both differences are below20%; HLS still omits finite-FIFO fill/drain and backpressure. T4 therefore needs physical validation rather than selection from its HLS prediction.

C15's preplanned5ns independent implementation is now eligible. At that target,300632cycles would equal1.503160ms,45.653% below W22's independently validated2.7658521ms; this is a conditional calculation, not a timing result. Accept a frame time only after C15 closes setup/hold and passes all routed resource/status gates. Preserve C13's historical HLS-infeasible status and the complete13-image deltaPSNR=-0.07589037644656216dB. No board latency has been measured.

All 2 RTL transactions pass. Maximum latency is 300632.0 cycles and interval is 300661.0 cycles; latency differs from the frozen HLS bound by 14.269641567524417%. Finite-FIFO/AXI handshake costs are included in RTL. This ideal-clock simulation does not establish routed timing or board latency.

The archived profiling/channels.csv and processes.csv locate FIFO backpressure and per-process stalls. Fast source/window producers are expected to block behind the T-fold MAC consumer; a large write-block fraction alone is not evidence that deeper FIFOs would improve frame throughput. Process counters span all recorded transactions and include startup/inactive cycles; overlapping stalls cannot be summed to explain the complete latency difference.
