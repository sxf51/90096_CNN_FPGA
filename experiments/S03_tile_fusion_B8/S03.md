# S03: tile_fusion_B8

## 1. Purpose and hypothesis / 目的与假设

Explore B=8 output-tile fusion. Cache(B+12)^2 input values and(B+4)^2 Conv2 features, fusing Conv1/Conv2 per feature center. Clamp each feature center to the true image before selecting its9x9 input patch, preserving replicate at Conv3. ## 6. Interpretation / 解读

Compare measured per-tile scheduling overhead, cache LUT use, halo recomputation and requested versus inferred burst lengths. DDR stalls are outside csynth's accurate model.

Whole-network DATAFLOW overlaps the dedicated layer engines. Tile fusion removes full feature maps but executes Conv1/Conv2 and Conv3 sequentially, recomputes halos, and can lose memory parallelism. Requested AXI burst limits are upper bounds; only inferred bursts are evidence of burst generation. DDR payload/bandwidth models exclude protocol stalls and are lower bounds.

The paper projection counted MAC lanes and cache bits, but omitted dynamic clamped spatial-bank selection and address logic. The tile pipeline reports isolate the MAC counts; the top's remaining DSP count includes address/control arithmetic. Conv1/Conv2 folds restart for every scheduled halo feature, then Conv3 runs sequentially. Even at II1, each restart pays the reported iteration depth; the scheduled halo ratio is shown in the DDR/cache table. These observed costs explain the LUT and cycle excess, rather than an unexplained multiplier-count increase.
