## 6. Interpretation / 解读

The16-entry feature FIFO passes both complete RTL transactions, including changed runtime weights/biases and the original butterfly border check. Latency558758 and interval558787cycles exactly match F97 and the32-entry F45 control. Functional verification passes, but the WS-D535741-cycle performance goal remains unmet; no latency improvement is claimed.

Observed features_U occupancy reaches16 rather than4. Producer write blocking falls from903830 to860078cycles over two frames, while consumer read blocking stays46990. The transformed-window read blocking stays45974 and its producer write blocking stays968784. Top-row read blocking grows from78136 to121888cycles. These counters show that deeper raster features redistribute backpressure without removing the upstream transformed-window supply gap. Stall totals overlap and are not additive frame-time costs. F48 independently tests that supply gap before selecting a FIFO route candidate.

The measured latency remains6.382071% above the525237 HLS component bound, below the20% estimate-audit threshold. Runtime weights, E017 exactness, the complete13-image precision evidence and source/RTL/init manifests remain unchanged. Physical storage cost and board latency have not been measured for F40.

Both RTL transactions pass. Maximum latency is 558758.0 cycles and interval is 558787.0 cycles; latency differs from the frozen HLS bound by 6.382071331608397%. Finite-FIFO/AXI handshake costs are included in RTL. This ideal-clock simulation does not establish routed timing or board latency.

The archived profiling/channels.csv and processes.csv locate FIFO backpressure and per-process stalls. Fast source/window producers are expected to block behind the T-fold MAC consumer; a large write-block fraction alone is not evidence that deeper FIFOs would improve frame throughput. Process counters span both transactions and include startup/inactive cycles; overlapping stalls cannot be summed to explain the complete latency difference.
