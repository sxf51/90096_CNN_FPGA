# W22: ws_clock_4p95_W21

## 1. Purpose and hypothesis / 目的与假设

Test one conservative physical-clock improvement on the exact W21 RTL that independently closed5ns in F98. F98's own first five paths identify three Conv2 parameter-FIFO-to-private-LUTRAM write-data paths and two Conv3 step-control-to-DSP-input paths, with routing-dominated delay and no DSP cascade. Tighten only the design clock constraint to4.95ns and measure timing/resources in a fresh workspace; preserve the5ns fallback. Also bound placement/routing to2 threads while keeping synthesis1 and the hardware lock serial. Runtime comparison is descriptive because clock and thread count both change; no isolated thread speedup claim is possible.

## 6. Interpretation / 解读

The fresh same-RTL implementation closes its actual 4.95 ns constraint: WNS +0.047 ns, TNS 0, WHS +0.032 ns, THS 0, TPWS 0, and zero unrouted nets. The detailed log reports WNS +0.046800 ns. Use 4.95 ns as the validated IP target; the report's 4.903 ns achieved-period figure is target minus slack and has not been separately implemented or tested.

The physical paper estimates are confirmed: DSP 644, FF 88,806, BRAM18K-equivalent 109, URAM 0, and LUT 42,592 versus the estimated 42,594 (-0.0047%). No physical-resource estimate deviates by more than 20%. Memory primitives are 46 RAMB36E2 and 17 RAMB18E2. Relative to the unchanged W21 HLS estimates, routed LUT/FF/BRAM remain substantially smaller because physical optimization, LUT combining and memory packing happen after HLS accounting. This mapping difference does not authorize replacing the original HLS resource gates; W21 retains only 898 LUT of HLS margin.

The 93-file RTL/init manifest matches W21 and F98 exactly. Therefore reuse F97's independently measured 558,758-cycle maximum latency and 558,787-cycle interval, including its changed-weight/bias second-frame check. This implementation experiment did not run a new cosimulation or measure new cycles. At the closed 4.95 ns target, the derived IP frame time is 2.7658521 ms and interval is 2.76599565 ms, exactly 1% less than F98's 5 ns point. Startup, finite-FIFO and AXI overhead remain 6.382071% above the 525,237-cycle HLS estimate. Board clocks, external DDR/driver time and the missing comic image are not validated by this result.

Four of the five setup paths now run from Conv3's pipeline-enable register through four logic levels (LUT2, LUT4, LUT5 and MUXF7) to inputs of one DSP. The worst data path is 4.325 ns, with 3.604 ns (83.329%) routing delay; an intermediate control net has fanout 956. Path 3 is Conv3's parameter FIFO to private weight LUTRAM write data: 4.715 ns total delay, 4.597 ns (97.497%) routing, fanout 101 and zero logic levels. No path uses DSP PCIN/PCOUT cascade. F98's worst Conv2 parameter-data path is not this run's bottleneck. Further independent work should isolate Conv3 control distribution or parameter fanout and account for added registers against the tight HLS LUT gate.

Implementation took 43.898946 minutes versus F98's 62.947585 minutes. Both synthesis hooks confirm general=1/synth=1, and the implementation hook confirms general=2/synth=1. Across 176 samples, mean total CPU busy is 12.983811% on 12 logical CPUs, mean load1 1.507330, minimum available memory 2.615864 GiB and peak tool RSS 12.013729 GiB. F98's corresponding CPU busy was 9.250086%, minimum available memory 3.011604 GiB and peak RSS 11.642307 GiB. This is a descriptive comparison with both clock and thread settings changed, not an isolated multithread speedup. The serial hardware lock and no-swap/global-settings policy were preserved; no OOM or timeout occurred.
